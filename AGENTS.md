# AGENTS.md

## Cursor Cloud specific instructions

This is a two-service monorepo ("Timesheet Tracker"): `apps/api` (FastAPI/Python) and `apps/web` (Next.js/React). Standard commands live in `README.md` and root `package.json`; prefer those. Notes below cover only non-obvious caveats.

### Services

| Service | Run command (from repo root) | Port | Notes |
|---------|------------------------------|------|-------|
| API (FastAPI) | `npm run dev:api` | 8000 | Runs `uvicorn app.main:app --reload` via the venv at `apps/api/venv`. |
| Web (Next.js) | `npm run dev:web` | 3000 | Next may hop to 3001/3002 if 3000 is busy; API CORS already allows those origins. |

Both services must be running to exercise the app end to end. Run them as long-lived processes (tmux/`terminals`), not in `install`.

### Testing (non-obvious)

- There is **no CLI test runner**. "Tests" are in-browser acceptance checks on the board at `http://localhost:3000` — click **"Run all tests"**. This requires the API to also be running.
- On a fresh scaffold, only the two **"Local scaffold"** tests pass (`API health`, `Progress board loads`); the other ~14 feature tests are **expected to fail (red)**. This is normal and does NOT indicate a broken environment — those features are the milestones interns build.
- Lint: `npm run lint --prefix apps/web`. The scaffold has a pre-existing ESLint error in `apps/web/src/components/ProgressBoard.tsx` (set-state-in-effect) and two warnings — these exist in committed code, not from environment setup.
- Build (prod, optional): `npm run build:web`.

### Database

- `apps/api/.env` and `apps/web/.env` are created from `.env.example` during setup with a **placeholder** `DATABASE_URL`. Nothing actually connects to Postgres yet, so the app boots and scaffold tests pass without a real DB. `GET /health` reports `database_url_configured: true` merely because the placeholder string is non-empty.
- A real Neon `DATABASE_URL` (from the Program Lead) is only needed once DB-backed feature milestones are built.

### Gotchas

- Running `next dev` (via `npm run dev:web`) rewrites/re-adds the managed rules block in `apps/web/AGENTS.md`, showing up as an uncommitted change. This is generated by Next.js; committing it with your work keeps the tree clean.
- `.env` files are git-ignored — never commit them.
